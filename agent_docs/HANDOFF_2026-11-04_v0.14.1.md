## 2. How to work here

**Commands**
```bash
npm ci && npm run build        # index.html is GENERATED, never hand-edit
node --test tests/<file>.js    # one unit suite
node tests/<file>-browser.js   # one browser suite (Playwright + the preinstalled Chromium)
npm test                       # ~8 min, 500+ unit tests
npm run validate:full          # ~30 min: build, release verify, unit, all browser suites, audit
npm run audit                  # engine balance
SEASONS=10 SEED=7 node tools/longrun.js   # multi-season stability, handles being fired
```
Engine tests use `tools/harness.js` (`loadEngine({ seed, fullRuntime })`); UI-extension variables exist only with `fullRuntime: true`.
New modules must be added to `tools/build.js` (engine extensions and CSS) and `tools/harness.js`.

**Shipping** (cloud sessions get 403 on release writes, so everything goes through Actions)
- `publish.yml`: dispatch `target=production`, `confirmation=PUBLISH` on the default branch. It re-validates everything, 15 to 21 minutes. Read the job result, not the run status (the run lags).
- `release.yml`: inputs `version`, `title`, `target` (commit SHA), `prerelease`, `note`. It refuses a version that does not match `VERSION.txt` at the target, a commit not on a remote branch, an existing release, or a missing CHANGELOG section.
- Version bump touches: `VERSION.txt`, `app.js` (`APP_VERSION`), `package.json`, `package-lock.json` (twice), `README.md`, `CHANGELOG.md`, `agent_docs/latest_session_work.md`, `agent_docs/project_progress.md`, `docs/roadmap/STATUS.md` (needs a real commit SHA behind HEAD). `tests/docs-consistency.js` enforces it.
- After a merge, a small docs-only PR records the merge, publish and release.

**Owner preferences (observed)**
- Wants decisive recommendations with evidence, not menus; wants honest reporting of mistakes and flaky results.
- Merge and publish only on an explicit go-ahead each time ("merge it and publish"). Pin merges to the validated head SHA.
- Skip the full local gate for UI batches: run targeted suites for what you touched, then rely on the PR's CI (it runs everything on version bumps).
- Does not need compatibility with current saves; no migration work.

**Pitfalls that cost us time**
- `git add -A -- . ':!node_modules'` fails on the ignored path and silently skips the commit.
- `pgrep -f` inside a Monitor matches its own command line and never exits; poll the output file instead.
- `verify:release` refuses a dirty tree: commit before `validate:full`.
- `test:browser-extended` is a `&&` chain: one failure hides every test after it. Fix, then run the remainder locally.
- Choose tests by grepping for **every selector you change**, not only the ones you interact with. Tests that wait for a roster table or `#depthGrid` to be *visible* break when it folds; open the toggle (`[data-rd-table-toggle]`, `[data-fold-toggle]`).
- About 30% of fresh dynasties open with no required Coach's Desk decision (`hasPendingWeeklyDecisions` ignores `WEEKLY_GAMEPLAN`), so Game Lab and Sim Week are not gated. A test that needs a gated week must sim forward until `#simWeek` is disabled; assert the invariant. Twelve lucky passes is not evidence: measure the rate.
- Under `set -o pipefail`, never pipe into a reader that exits early (`awk exit`, `grep -q`, `head`).
- `applyEarlyCommitments` must run after `recruitClassCounts={}` and the per-team `t.commits=[]` reset in `offseasonPreseason`, or the counts are wiped.
- A detector can lie: run it against the old build and confirm it fails before trusting a green.

3. **Branch hygiene.** About 140 remote branches, most old `claude/*` and `codex/*`, plus `temp-do-not-use`. Do not delete without asking.

**Engineering backlog (ranked by my judgment)**
1. **Save size grows about 9 MB per season** (36.8 MB at season 1, about 125 MB at season 10; same on the old base). `docs/SAVE_SIZE_MEASUREMENT.md` is stale. Re-measure, find what dominates (probably the archive and event history), trim. Impact on load/save time is unmeasured.
2. **Run `tools/league-health.js`** over 10 seasons. It has not been rerun since specialist recruits and the smoothed class sizes.
3. **Rising class, next steps:** in-season AI pursuit (today only at rollover), visits for rising prospects, the 600-prospect cap.
4. **Real quarter scores.** Archived drives store points and result but not the quarter; the Watch view's clock labels are reconstructed. The engine needs to record the quarter per scoring drive. Do not derive them from the reconstructed clock.
5. **Long pages:** History index on a phone (about 3,700 px), Recruiting (about 5,000 to 7,000 px). `table-folding.js` makes folds easy.
