## What was added

All four are **engine extensions**: self-contained files that wrap engine functions by reassigning them. They're listed in
`tools/build.js` (`engineExtensionFiles`) **and** `tools/harness.js` (`runtimeExtensions`), in this order, after
`offseason-stops.js`: `realignment.js`, `locker-room.js`, `noncon-schedule.js`, `nfl-pipeline.js`. They run only in the
built game and in `loadEngine({fullRuntime:true})`. The plain harness, which most older tests use, does not load them.
None of them draws from the gameplay random stream; randomness comes from FNV-style hashes of ids, seasons and weeks, so
reloading a save never changes an outcome. Shared styles live in `dynasty-world.css`, which is in the build CSS list after
`facilities-boosters.css`.

### 1. Conference realignment — `realignment.js` (v0.32.0)
- **Brand** = prestige×.6 + fan support×.25 + facilities×.15. **Media value** = the conference's mean brand. **Payout by media
  rank:** 4,4,3,3,2,2,1,1,0,0 units into each member's booster fund every offseason (wraps `resetNilSeason`).
- **Window:** every 4th offseason, counted from `universe.realignment.startYear`. It runs in a wrap of `offseasonReview`,
  after the season is archived.
- **Swap rule:** neighbouring conferences in the media ranking trade one-for-one. The stronger one takes the most
  appealing of the weaker one's top 3 brands, with appeal = brand − 1 per 250 miles to the conference centre, if it is
  ≥8 clear of its own weakest member. At most 2 swaps, one per conference. Sizes stay at 12, so `buildSchedule` is untouched.
- **Rivalries:** broken rivalries are recorded in the move history; the four programs left without a rival are re-paired
  with `deriveRivalries()`.
- **Invitations:** an invitation to the coach's program is stored in `realignment.pending`. It is answered on This Week (a
  card before `#weeklyDecisions`), and the Next button stops once (wraps `globalThis.DynastyOffseasonStop`). It is settled
  as "stay" in a wrap of `offseasonPreseason`. Commissioner mode never asks.
- **UI:** Program page card `#conferenceOutlook` (media rank, payout, brand standing, rising / at-risk / watching /
  settled outlook, member and ranking tables, move history).
- **State:** `universe.realignment {startYear, history (cap 40), pending, lastWindow, lastPayout, declined}`.

### 2. Locker room — `locker-room.js` (v0.32.0)
- **Personality:** Leader 10%, Competitor 20%, Steady 45%, Quiet 15%, Volatile 10%, from a hash of the player id. Not saved.
- **Leadership:** class year, ability, staff trust, morale and personality.
- **Captains:** 4 (the staff pick 2 per side and never K/P). The coach can change them on the Roster page while
  `week===0`. `p.captainYear` gives −6 transfer risk (wraps `transferRisk`).
- **Chemistry:** `t.lockerRoom.chemistry` blends 25% a week toward a target built from captains' leadership, core-44
  morale, the last 3 results, unhappy Volatile players and contented Leaders. Effect is clamp((chem−55)/20, −1.5, +1.0)
  on offense and defense for **every** team (wraps `profiles`). Chemistry ≥70 lifts morale; <40 wears it down.
  A new season keeps half (wraps `offseasonPreseason`).
- **Flashpoints:** coach's program only. Odds come from a hash of program, season and week. Options: discipline, back him,
  or leave it to the captains. If the coach doesn't answer, the captains handle it **after** the next week is played. That
  must not happen before the week: a live game locked in at kickoff checks the roster digest, which was a real bug, fixed
  in `f021698`. Two straight losses with a Leader captain bring a players-only meeting (+6, once a season).
- **UI:** Roster page card `#lockerRoom`; flashpoint card `#lockerRoomFlashpoint` on This Week.

### 3. Nonconference scheduling — `noncon-schedule.js` (v0.32.0)
- A trade swaps the coach's opponent with the **same-side** team from another nonconference game that week, so home
  counts never change. `validateSchedule()` runs after each trade, and the trade is reverted on any problem.
- **Limits:** 2 trades a season, only for games more than a week out (`g.week > universe.week+1`), so this week's decisions,
  such as the game plan, never point at a stale opponent.
- **Money:** a buy game costs 1 booster unit. **Any** marquee home game, traded or not, pays +2 goodwill and +1 fan
  support when played (wraps `simWeek`).
- **UI:** Season page card `#nonconSchedule` (wraps `TAB_RENDERERS.season`, because `renderSeason` doesn't use
  `runRender`). It shows a shortlist mixing marquee, regional, buy and standard options.
- **State:** `t.nonconPlan {year, trades, paid}`.

### 4. Pro pipeline — `nfl-pipeline.js` (v0.33.0)
- **`draftProjection` is replaced.** Grade = ability×.66 + position NFL traits×.16 + production×.12 + room×.2 +
  durability/injuries + exposure + style translation (`STYLE_NFL` table) + a fixed hashed scouts' read + `GRADE_OFFSET`.
  Board score = grade + positional value×.8 (`POS_VALUE`: QB +4 … K −8, P −9). Round thresholds are unchanged, so early
  declarations read the same function.
- **`runDraft` wrap:** stores `pg` and `pc` (grade, ceiling) on drafted records, and on undrafted records graded ≥74
  (`UDFA_KEEP`). It also patches the archived player's copy of `draftResult`; `archiveRecord` copies only a few fields.
- **Careers are derived, never stored.** `career(record)` is a pure function of `pg`, `pc`, round, pick, position and
  hashes of the player id. Parameters are in `CAREER` (boom, bust, bloom, pro-bowl floor and centre, and so on).
  `careerAt(record, year, seasonOver)` slices it to the seasons played so far (the rookie season is the fall after the
  draft).
- **Payoffs:**
  - `allSchools()`: a per-school summary, cached per season with a constant-time freshness check.
  - A "Pro pipeline" row in `recruitPitchBreakdown`: rank-based, up to +4, scaled by pipeline size, plus up to +1.5 at the
    recruit's position.
  - Alumni gifts (0–2 units into the booster fund, wraps `resetNilSeason`).
  - `PRO_MILESTONE` events for the coach's alumni (wraps `offseasonReview`, at most 6 a year).
  - Program page card `#proPipeline`.
  - A pro career or NFL outlook block appended to `careerChronologyHTML`.
- **State:** `universe.nflPipeline {reviewed, lastGift}`, plus `pg`/`pc` on draft records.

## Issues and risks I see

1. **The browser and accessibility suites were not run in full.** Only the new browser test ran. Run
   `npm run test:browser`, `npm run test:browser-extended` and `npm run test:accessibility`. Four new cards and two new
   This Week cards could trip axe rules (heading order: the cards use `h3` and `h4`), phone floors, or tests that count
   cards or regions on This Week.
2. **Balance was measured for v0.32, not v0.33.** Alumni gifts add booster money to AI programs, and the pipeline pitch
   tilts recruiting toward pro factories, which are usually already strong. That's a rich-get-richer risk. Re-run:
   `FULL=1 SEED=7 SEASONS=10 node tools/league-health.js` (plus seeds 11, 23 and 31) and compare against the table in the
   measurements doc.
3. **Early declarations are probably lower.** In calibration, seniors scoring 88+ dropped from 16 to 9, because the old
   formula's per-call noise pushed more players over. Juniors declare only for rounds 1–2. If the draft feels thin on
   juniors, raise `GRADE_OFFSET` (1 → 1.5) or loosen the threshold in `earlyDeclaration` (app part 08). Measure
   early-declaration counts first.
4. **The Hall of Fame is somewhat generous:** about 4 per class at a 30-year horizon. The rule is in `careerAt`. Tighten it
   if it feels cheap.
5. **The invitation flow has never been clicked in a browser.** The announcement shows only in `phase==='complete'`. The
   unit tests cover the logic, and `__DL_TEST__.realignmentInviteFixture()` exists, but no browser test reaches an
   offseason with it.
6. **Realignment for older saves:** `startYear` is set lazily the first time the state is touched (Program page render or
   offseason review), so the first window is four seasons after that.
7. **Pro careers are keyed by the school name at draft time** (`record.school`). A commissioner-mode rename splits a
   program's alumni.
8. **AI programs never decline a realignment invitation**; only the coach can. The pipeline in a small conference is
   deterministic: same brands, same moves.
9. **The locker room runs `weekly()` for all 120 teams every week**, sorting each roster. That's cheap, but it wasn't
   profiled separately.
10. **A marquee home game pays out even if the rotation dealt it** (not traded). That's intentional; say so in the UI if
    players find it confusing.
11. **Two local git worktrees** (`old`, `v032`) were created under the session scratchpad for measurements. They are not
    in the repo; `git worktree prune` cleans the references if they appear.

     carousel and the game engine.
   - **Conference expansion past 12.** This needs a schedule builder for uneven conference sizes.

## Conventions worth keeping

- New gameplay features have been built as engine extensions that wrap existing functions. Add a new file to **both**
  extension lists, and to `package.json` test lists.
- Avoid the gameplay random stream for new systems; hash ids instead (see `hash()` in any of the four files).
- Every version bump touches `VERSION.txt`, `app.js` `APP_VERSION`, `package.json`, `package-lock.json`, `README.md`
  ("Current version"), the `CHANGELOG.md` heading, `agent_docs/latest_session_work.md` and `docs/roadmap/STATUS.md`
  ("Last reconciled ... source `<sha>` (`v<version>`)"; the sha must be an ancestor of HEAD). Then run `npm run build`
  and commit `index.html` and `sw.js`.
- Measure before tuning, and record measurements in `docs/`.
